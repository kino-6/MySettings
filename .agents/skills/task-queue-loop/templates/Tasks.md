> **READ FIRST（全エージェント / 全セッション）**
> 憲章（目的・ゴール・アプローチ・完了の判断）は [CHARTER.md](CHARTER.md)。ここは**具体作業だけ**を書く。
> **毎周の入口でこのファイルと CHARTER.md を読む。** 題が下のどれにも無ければ、**脇道と明記してから**回す。
> **上から 1 件ずつ**処理する。詰まったら `[~]` / `[!]` に理由を書いて次へ。2 件を同時に開かない。
> このファイルは **200 行以内**に保つ。超えたら幅を広げず、履歴へ移す。**commit の粒度で整備する。**

次に起票する ID は **<T001> 以降**。

## 書き方

1 行 1 作業。列は「**何を・なぜ・最小検証・Gate・状態**」。状態は必ずチェックボックスで書く。

- `[x]`: Gate と必要な画像判定まで完了。**直近 1 件だけ**境界確認用に残し、以後は履歴へ移す
- `[-]`: 進行中。中断時も、どこまで済んだかを状態欄へ併記する
- `[~]`: 人間の判断が必要（**何を決めてほしいか**と、こちらで決めなかった理由を書く）
- `[ ]`: 未着手、または外部判定待ち。途中まで済んだ場合は内訳も `[x]` / `[ ]` で併記する

**Gate は完了を証明するコマンドと、その出力が満たす条件**にする（通ったかどうかが機械か画像で分かる形）。
**Gate と再現コマンドが書けないものは、まだ課題になっていない。** 「気になる」段階なら先送りへ置く。

**最小検証は Gate と同じ扱いで、同じときに書く。** この行の変更が効いたかどうかを**最短で**見る
コマンドと条件で、Gate と同じ契約（コマンド + 条件 + 落とせること）を負う。違うのは**頻度**だけ:

- **最小検証は毎回回す。** 1 ファイル / 1 挙動に絞る（`--only=<file>` / `--lane=<name>` / 1 seed / 1 画面）。
  秒で返らないなら、まだ絞れていない
- **Gate は commit 直前に一度だけ回す。** 反復のたびにフル Gate を回すのが、この進め方が遅くなる主因
- **赤を確かめるのは最小検証で先にやる。** 安いほうで落ちることを見てから実装に入る
- **最小検証が緑で Gate が赤なら、それは情報**（絞り方が狭すぎた）。次の周で最小検証の側を直す
- **この行に対して落とせない最小検証は、最小検証ではない。** Gate を薄めただけのものを書かない

**遅いと感じたら、絞る前に並列化しない。** 絞ってもまだ遅いときだけ、下の順で検討する:
同じ木で並列に回すとキャッシュやロックを奪い合うので、**複製した木と専用ロックへ逃がす**
（長い Gate を裏で回しながら、手元では最小検証だけを回す）。掃引・seed 違い・独立した行の監査は
並列にしてよい。**順序や状態に依存する不具合を追っているときは並列にしない**（再現しなくなる）。

**完了（`[x]`）の 4 条件** — 4 つ揃うまで `[x]` にしない。
1. 最終 Gate が緑（`test.fail()` / xfail の裏に隠れていない）
2. 実画面・実値を**自分で**確認した（headless の pass を見た目の合格に読み替えない）
3. 1 コマンドの再現手段が行に書いてある
4. commit 済み

**人間の通しプレイは完了条件にしない。**

**`[x]` にする前に、別視点の検証を 1 回通す。** 実装した文脈は Gate の緑を「確認」として読むので、
**Gate を書いた本人が完了を判定しない**。別セッション / 別エージェントに、**差分ではなく Gate を攻めさせる**:
差分を戻して Gate が**赤くなること**、挙動を壊して**赤くなること**、再現コマンドが本当に現物を出すこと。
戻して緑なら、その Gate はこの修正を測っていない —— **コードより先に Gate を直す**。
検証が出した refactoring 案は、**Gate 付きの行**にしてこのキューへ積む（Gate が書けない案は捨てる）。
