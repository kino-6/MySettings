# Tasks.md — 作業のブレークダウン

> **READ FIRST（全エージェント / 全セッション）**
> 憲章（目的・ゴール・アプローチ・完了の判断）は [CHARTER.md](CHARTER.md)。
> 作業規律（Gate と最小検証の契約 / 完了の 4 条件 / 別視点の検証 / 並列化）は [work-rules.md](<docs/work-rules.md>)。
> **ここは具体作業だけを書く。決まりを写さない。**
> **毎周の入口でこのファイルと CHARTER.md を読み、`[x]` を付ける前に work-rules.md を読む。**
> 題が下のどれにも無ければ、**脇道と明記してから**回す。
> **上から 1 件ずつ**処理する。詰まったら `[~]` / `[!]` に理由を書いて次へ。2 件を同時に開かない。
> このファイルは **200 行以内**に保つ。超えたら幅を広げず、履歴へ移す。**commit の粒度で整備する。**

次に起票する ID は **<T001> 以降**。

## 書き方

1 行 1 作業。列は「**何を・なぜ・最小検証・Gate・状態**」。状態は必ずチェックボックスで書く。

- `[x]`: Gate と必要な画像判定まで完了。**直近 1 件だけ**境界確認用に残し、以後は履歴へ移す
- `[-]`: 進行中。中断時も、どこまで済んだかを状態欄へ併記する
- `[~]`: 人間の判断が必要（**何を決めてほしいか**と、こちらで決めなかった理由を書く）
- `[ ]`: 未着手、または外部判定待ち。途中まで済んだ場合は内訳も `[x]` / `[ ]` で併記する

**最小検証は毎回・秒で。Gate は commit 直前に一度。** どちらも「コマンド + 条件」で書き、落とせること。
**再現は検査ではない**（合否を持たない。人を現物の前に立たせるだけ）。
**Gate と再現が書けないものは、まだ課題になっていない。** 「気になる」段階なら先送りへ置く。

**完了の 4 条件と、`[x]` の前に通す別視点の検証は [work-rules.md](<docs/work-rules.md>)。**
