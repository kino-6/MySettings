# 作業規律

> やることの一覧は [Tasks.md](Tasks.md)。憲章は [CHARTER.md](CHARTER.md)。
> **ここは守るべき決まりだけを置く。着手前と、`[x]` を付ける前に読む。**
> Tasks.md 側には決まりを写さない。同じ問いに読み手が 2 つあると、片方だけ直して黙ってずれる。

## 行が備えるもの

1 行 1 作業。列は「**何を・なぜ・最小検証・Gate・状態**」。

**Gate は完了を証明するコマンドと、その出力が満たす条件**にする（通ったかどうかが機械か画像で分かる形）。
**Gate と再現コマンドが書けないものは、まだ課題になっていない。** 「気になる」段階なら先送りへ置く。

曖昧語は数値とキー名へ落とす。「はみ出さない」ではなく「1280×720 で下端 ≤ 720 を assert」。
**反対の人が走らせても同意せざるを得ない形**になっているかで判定する。

## 最小検証と Gate と再現

3 つは役割が違う。**最小検証と Gate は同じ契約**（コマンド + 条件 + 落とせること）を負い、違うのは頻度だけ。

| | 最小検証 | Gate | 再現 |
|---|---|---|---|
| 問い | この行の変更は効いたか | この行は完了か | どう見えるか |
| 返すもの | 合否 | 合否 | 現物 |
| 範囲 | 1 ファイル / 1 挙動 / 1 seed / 1 画面 | 全体・帯域・実画素 | 1 つの状態 |
| 頻度 | 毎回 | commit 直前に一度 | 人が見たいとき |
| 予算 | 秒 | かかるだけ | 1 コマンド |

**再現は 3 つ目の検査ではない。** 合否条件を持たず、何も証明しない。
人を現物の前に立たせるためだけにある。最小検証に吸収させないし、代わりにもしない。

### 最小検証の規則

- **Gate と同じときに、着手前に書く。** 後から決めると、反復はぜんぶ高いほうで回り終わっている
- **1 ファイル / 1 挙動に絞る**（`--only=<file>` / `--lane=<name>` / 1 seed / 1 画面）。秒で返らないなら絞れていない
- **赤を確かめるのは最小検証で先にやる。** 安いほうで落ちることを見てから実装に入る
- **この行に対して落とせない最小検証は、最小検証ではない。** Gate を薄めただけのものを書かない
- **最小検証が緑で Gate が赤なら、それは情報**（絞り方が狭すぎた）。コードを直す同じ編集で最小検証を広げる

### 並列化

**絞る前に並列化しない。** 8 並列のフル Gate はやはりフル Gate で、1 秒の検査にコアは要らない。
絞ってもまだ遅いときだけ、下を検討する。

- **効く**: 長い Gate を複製した木で裏に回しつつ手元は最小検証だけ / 掃引・seed 違い / 独立した行の監査をまとめて投げる / ファイル単位で既にプロセス隔離しているランナーの並列数を上げる
- **効かない**: 同一の木・同一ロック（キャッシュを奪い合ってハングか破損になる）/ 順序・状態に依存する不具合（再現しなくなり「直った」と誤読する）/ **人が読まねばならない出力**（並列に出た 4 枚は結局 4 回見る）/ どれが落ちたか分からなくなる harness

並列に回してよいレーンは行に書き残す（`（seed 5 本は並列可 / 同一木では不可）`）。次の周が調べ直さずに済む。

## 完了の作法

**完了（`[x]`）の 4 条件** — 4 つ揃うまで `[x]` にしない。

1. 最終 Gate が緑（`test.fail()` / xfail の裏に隠れていない）
2. 実画面・実値を**自分で**確認した（headless の pass を見た目の合格に読み替えない）
3. 1 コマンドの再現手段が行に書いてある
4. commit 済み

**人間の通しプレイは完了条件にしない。** 確認をユーザへ振らない。
ユーザに渡すのは**好みや製品判断が要る問い**だけで、検証の作業は渡さない。

### `[x]` にする前に、別視点の検証を 1 回通す

実装した文脈は Gate の緑を「確認」として読む（何を直したかを知っているため）。
だから **Gate を書いた本人が完了を判定しない**。別セッション / 別エージェントへ、
**なぜ正しいかの説明を渡さずに**、行・差分・Gate コマンド・成果物だけを渡す。

攻めるのは**差分ではなく Gate**。

1. **差分を戻して Gate を回す。赤くなること。** 緑ならその Gate はこの修正を測っていない
   （差分が test / tool だけの行では定義できない。理由を書いて 2 へ）
2. **挙動を壊して回す。各々で赤くなること。** 生き残った変異が穴の名前になる
3. **同じ変異で最小検証も赤くなること。** Gate が赤いのに緑なら、自分の変更が見えない検査で反復していた
4. **assertion が実際に走ったか**（空マッチ・skip された fixture・0 件ループは静かに通る）
5. **再現コマンドを逐語で実行**し、成果物を**自分の言葉で**述べる

**戻して緑なら、コードより先に Gate を直す。**
検証が出した refactoring 案は、**Gate 付きの行**にしてキューへ積む（Gate が書けない案は捨てる）。

## やらないこと

- 赤い Gate で commit / push する。「無関係」と決めつけて放置する（無関係なら基準ブランチで再現することを先に示す）
- フル Gate で反復する（最小検証を書いていないか、広すぎる）
- 絞る前に並列化する
- headless の pass を見た目の合格に読み替える
- 未承認の将来案をキューに混ぜる
- 行を閉じるためだけに無関係な差分を 1 つの commit にまとめる
- Gate の無い行を置く（書けないものは課題ではない。先送りへ）
