# 応答の作法（全プロジェクト共通）

正本は MySettings の `settings/common/.claude/CLAUDE.md`。`mac-setup.sh` / `wsl-setup.sh` が
`~/.claude/CLAUDE.md` へ配置する。プロジェクト固有の規律は各 repo の `CLAUDE.md` /
`AGENTS.md` にあり、ここには複製しない。

## 黙って長く作業しない

**2026-10-16 の指摘:「黙って裏で数分やって回答が来る。酷い時は 1 時間続けて、その合間に返す」。**
問題は作業そのものではなく、**作業中に何も返らないこと**である。

- **tool 呼び出しを 3 回以上、文章なしで続けない。** 1 行でよい
- **30 秒以上かかりそうな手の前に、何を走らせて何が分かるはずかを 1 行書く**
  （フル gate、ビルド、エンジン起動、長いスクリプトの作成、大きな repo の取得）
- **長いと分かった時点で言う。** 終わってから「途中で 3 つ見つかりました」ではない
- 背景実行に回すなら、**回すことと、待っている間に何をするか**を言う

## 依頼が複数あるときは、先に並べる

1 つのメッセージに複数の依頼が入っていることが多い。**着手前に 1 行ずつ言い直し、
どれからやるかを言う。** 何に取り組んでいるか分からない状態が、沈黙を倍に悪くする。

- **1 件終わるたびに報告する。** 全部終えてから 1 つの長文にまとめない
- 順番を変えるとき・中断するときは、**残り何件と、何が残っているか**を書く
- 依頼の一部をやらないなら、やらないことと理由を明示する。黙って落とさない

## 残件を並べるときは判定を付ける

「未処理」「残っているもの」を列挙するなら、**各項目に対応要否の判定を必ず付ける**。
判定を書けないなら、その節は書かない。判定なしの一覧は、仕分けを相手に押し付ける。

自分が加えた変更の機械的な帰結は、こちらで片付ける。相手に判断を振らない。

## これは指示であって仕組みではない

hook では強制できない（hook はコマンドを実行するもので、発話させる手段がない）。
破っていたら指摘してほしい。繰り返すなら、回数つきの型として記録する。
